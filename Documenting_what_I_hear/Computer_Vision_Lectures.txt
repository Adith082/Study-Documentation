Deep Learning's vanishing gradient problem
In very deep networks, during backpropagation, gradients often:

Shrink exponentially
Fail to update early layers
This means:
Shallow layers stop learning
Network gets stuck in a suboptimal state

Shallow layers = First few convolutional layers
Why is this a problem?
The shallow layers are critical - they detect edges, textures, shapes.
But if they do not receive gradient signals, they cannot improve.
Your model becomes stuck - training error stays high.

This is not overfitting. It is undertraining - the model cannot learn due to bad optimization.


Mathematical intuition of vanishing gradient
Most activation functions (like sigmoid or tanh) squash inputs into small ranges:
Their derivatives are less than 1, often between 0 and 0.25.

During backpropagation, the chain rule multiplies these small numbers:

The gradient vanishes - and early layers stop learning.


The Breakthrough: Residual Learning
Kaiming He et al. (2015) at Microsoft Research asked a simple question:

What if the layer does not learn a full transformation?
What if it only learns the residual?
They proposed:
Now instead of learning a complex function directly, the layer just learns what to add to the input.

This simple idea changed everything.


Skip Connections (Shortcut Paths)
ResNet solved vanishing gradient forever!
Instead of expecting each layer to learn a completely new representation, ResNet builds “residual connections” (also known as skip connections) that allow the original input to flow directly to deeper layers.

In mathematical terms, each residual block receives an input X and learns only the change needed to transform X into a better representation. 

Formally, it outputs X+F(X), where F(X) denotes the learned residual function.
This design ensures that early-layer activations can pass straight to the final output, preserving their influence on the network’s predictions. 

By allowing the gradient to flow back without getting diluted through many transformations, ResNet effectively addresses the vanishing gradient problem. 

As a result, even very deep networks (sometimes hundreds of layers) can be trained successfully, because initial layers still receive strong updates.


ResNet killed all other competitors in 2015
Shortly after its introduction, ResNet dominated the ImageNet Large Scale Visual Recognition Challenge (ILSVRC) 2015. 

In the classification task, ResNet-based models achieved a top-5 error rate that surpassed all competitors. This victory signaled a major leap in performance, as it was the first time a network of such depth could outperform shallower architectures so convincingly.


In addition to the classification challenge, ResNet scored first place in the ILSVRC 2015 detection, localization, and segmentation tasks. 


It also delivered winning results in the Microsoft COCO detection tasks that same year. 

These back-to-back achievements quickly established ResNet’s reputation as a formidable architecture, influencing how future deep models would be built.

The ILSVRC subset (often called “ImageNet” in practice): This is the version used for the ImageNet Large Scale Visual Recognition Challenge (ILSVRC). It has around 1.2 million training images, 50,000 validation images, and 100–150,000 test images, spread across 1,000 classes.


Why is residual link such a big deal?
Consider the task of improving the resolution of an image starting with a blurred image. You can train a neural network such that it directly predicts the final output, which is the high-resolution image.
NOTE 1: ResNet only learns the necessary change
NOTE 2: In ResNet block, dimensions remain unchanged
Output=Input+F(Input)


If dimensions remain unchanged, how can you do classification?
A common point of confusion with ResNet is how it can perform tasks like classification if its residual blocks keep the same dimensions. 

After all, if each block preserves height, width, and number of channels, does that not suggest the network simply “enhances” the input image rather than transforming it into class scores?
NOTE 1: Residual blocks preserve dimensions only locally
NOTE 2: Dimension can change from one stage to another
Strided convolutions: A convolution layer with a stride greater than 1 (usually stride = 2) halves the spatial dimension (height and width) while often doubling the number of channels. In the example below, the stride is 3. Thus the input dimension (9x9) is reduced by a factor of 3 (3x3).
Downsample connections: If the skip path must match a changed shape, a 1x1 convolution (or a similar method) adjusts the input’s dimension so it can be added correctly.
NOTE 3: Classification through global pooling and a fully connected layer
Global average pooling: ResNet usually ends with a global average pooling layer that collapses the spatial dimension (e.g., 7x7) into a 1D vector by averaging across each channel.

Fully connected layer: This condensed vector then passes to a fully connected (dense) layer. The output of that layer corresponds to class scores (for example, 1,000 scores for ImageNet).


ResNet as an Euler method
From a theoretical standpoint, ResNet can be viewed as an Euler method in the sense that each residual block represents a small “update” or “step” to the input:
output=input+F(input)

MobileNet core idea – Depthwise separable convolution
Traditional convolution is computationally expensive.
A single standard conv layer with:
3×3 filter
32 input channels
64 output channels
 … requires 3×3×32×64 = 18,432 parameters!


MobileNet does this differently:

🔸 Depthwise Convolution
Applies one filter per input channel
 → Captures spatial information
 → Much cheaper (3×3×32 = 288 params)


🔸 Pointwise Convolution
Applies a 1×1 convolution across all depth slices
 → Combines information across channels
 → 1×1×32×64 = 2,048 params

✅ Total: 288 + 2,048 = 2,336 parameters
v/s 18,432 in standard conv!

That is nearly 9× fewer parameters with very little accuracy loss.

Each layer gets input from all previous layers in a feedforward fashion:



DenseNet benefits

Every layer receives inputs from all previous layers. So:
It does not need to relearn the same features
It selectively uses useful features
This reduces the complexity of what each layer has to learn
➡️ Less overfitting, because the model does not waste capacity learning redundant things.
Feature reuse - every layer has direct access to gradients and inputs from earlier layers

Fewer parameters than traditional networks

Improved gradient flow - solves vanishing gradient better than plain deep nets
Implicit regularization - discourages overfitting

HOW?

Let’s say we have 3 layers inside a dense block:
Layer 1 takes the input image and produces x1
Layer 2 gets the original input + x1, concatenated along the channel dimension
Layer 3 gets original input + x1 + x2 as its input
Dense block:
Uses concatenation instead of addition like ResNet
Each layer produces a fixed number of output feature maps called growth rate

So if each layer adds new features, those are stacked, not added.
This is called dense connectivity.

Think of DenseNet like building a conversation where every new speaker hears everything said before, rather than just hearing the last sentence.

EfficientNet: Scaling CNNs 
the smart Way
📘 Paper:
“EfficientNet: Rethinking Model Scaling for Convolutional Neural Networks” (2019) by Mingxing Tan and Quoc V. Le, Google.

Problem:
Traditional models scale arbitrarily by:
Adding depth (more layers)
Adding width (more channels)
Increasing image resolution
But this scaling is unbalanced and inefficient.

EfficientNet’s key idea is:
"Let us scale all three dimensions - depth, width, and input resolution - at the same time, using a compound formula, so the growth is efficient and balanced."

Why EfficientNet uses compound scaling
Traditional CNNs are scaled up to improve accuracy - by adding more layers (depth), more channels (width), or using higher-resolution images. But this is often done manually and inconsistently, requiring extensive trial and error with only modest gains.
EfficientNet solves this by introducing compound scaling - a method that scales depth, width, and resolution together using a single factor. This leads to better accuracy and efficiency without increasing model size unnecessarily.

The bold Idea at Google brain
In 2017, a team at Google Brain, led by Barret Zoph and Quoc Le, asked a radical question:
"What if we let a neural network design another neural network?"
Instead of coding the architecture ourselves, what if we trained a controller model - an RNN - to search through the space of possible architectures and figure out what works best?

This was the birth of NASNet - Neural Architecture Search Network.

How NASNet Works
Google trained a controller RNN that generates descriptions of architectures (called cells).

Each architecture was then trained and evaluated on CIFAR-10.

The validation accuracy was used as the reward for the controller.
The controller was updated using reinforcement learning to generate better architectures in future rounds.

NASNet is like giving a child Legos and asking them to build a castle. The better their creation, the more praise they get - and they learn what works over time.


Neural Architecture Search

NASNet in 3 Steps

Step 1: Use an RNN Controller
Think of an RNN as an "architecture generator." It creates possible CNN designs by choosing operations like:
3×3 conv
5×5 conv
max pooling
identity (skip)
where to connect which layers

This RNN generates small building blocks called cells.
This process is very expensive - Google's search used:
500 GPUs for 4 days
Thousands of architecture evaluations
But once the best cell is found, it can be reused in many settings.



Two Types of Cells:
Normal Cell: Keeps the spatial dimensions the same
Reduction Cell: Reduces the size (like pooling)

Step 2: Try and Train
Each generated cell is turned into a small CNN and trained on a small dataset (e.g. CIFAR-10).


After training, we evaluate its accuracy.


That accuracy becomes the reward for the RNN.
Using reinforcement learning, the RNN improves its architecture generation over time.

Step 3: Build the Full NASNet
Once the best-performing cells are found:
They are stacked multiple times to build the full network
This is done for large datasets like ImageNet
Why not just use 3×3 conv everywhere?
Because:
The NASNet search found that mixing operations like 1×1 conv, depthwise conv, skip connections, pooling, and 5×5 sep conv gave better results for both accuracy and efficiency.
